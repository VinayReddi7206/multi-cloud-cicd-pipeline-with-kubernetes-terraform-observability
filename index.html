01 / DELIVERY

Every release
has to earn it.

Open a stage to see what it checks and why it matters. The evidence links lead to the actual workflow and validation records.

Read the complete workflow ↗
01Test the changeNode.js · Terraform · Helm+

Application tests check API behavior and graceful shutdown. Terraform validation checks both cloud configurations. Helm lint and rendering cover Local, Dev, Staging and Production.

Explore the application and tests ↗
02Check securityCheckov · Trivy · non-root container+

Checkov scans infrastructure with documented exceptions. Trivy blocks the image on HIGH or CRITICAL findings, including unfixed vulnerabilities. The application runs as a non-root user.

Review security coverage and exceptions ↗
03Deploy the tested imageDocker · kind · Helm+

CI loads the scanned Docker image into a temporary local Kubernetes cluster. Helm deploys the service, then checks verify its identity, readiness and Prometheus scrape health.

Inspect deployment verification ↗
04Observe the servicePrometheus · Grafana · Alertmanager+

Six dashboard panels cover traffic, server errors, p95 latency, application memory, pod CPU and pod memory. CI also checks Grafana authentication and the Prometheus data source.

View the recorded monitoring results ↓
05Prove recoveryFailed upgrade · pod replacement · outage+

A deliberately unavailable image triggers a real Helm rollback. A deleted pod is replaced. A controlled outage fires the two-minute availability alert; restoring the service clears it in Prometheus and local Alertmanager.

Read the verification history ↗
